## Project Overview

**Healthcare Patient Risk Prediction** is an end-to-end, production-grade Machine Learning web application designed to evaluate patient risk for four major chronic conditions:
- **Diabetes** (Metabolic & Glycemic Markers)
- **Heart Disease** (Coronary Indicators & Exercise Stress ECG)
- **Chronic Kidney Disease (CKD)** (Renal Biomarkers & Urinalysis)
- **Liver Disease** (Hepatic Enzymes & Serum Proteins)

The application provides a unified, responsive interface where healthcare students, researchers, or triage personnel can enter real clinical parameters, select a disease module, and obtain real-time, probabilistic risk classifications generated by trained Scikit-Learn models.

---

## Problem Statement

Healthcare diagnostics generate high volumes of clinical laboratory values, biochemical assays, and physiological vitals. In emergency triage or preliminary screening:
1. **Multi-Parameter Complexity:** Synthesizing 8 to 24+ interacting lab parameters manually introduces cognitive load and diagnostic delay.
2. **Missing & Noisy Data:** Medical records frequently suffer from incomplete lab reports, unit variances, and biological anomalies (e.g., zero glucose in living patients).
3. **Early-Stage Asymptomatic Progression:** Chronic conditions such as kidney disease and coronary artery disease often progress silently without overt early symptoms.

---

## Proposed Solution

A lightweight, robust web-based decision-support system featuring:
- **Four Independent Classifiers:** Disease-tailored pipelines with separate preprocessing rules, avoiding one-size-fits-all compromises.
- **Strict Data Cleaning Pipelines:** Handling missing values, biological zeros, and encoding without data leakage.
- **Fast Local & Cloud Execution:** Sub-50ms inference via memory-resident preprocessors and models serialized with Joblib.
- **Privacy by Design:** Patient name is used purely for customized report rendering and is never persisted to disk or stored in any database.

## Data Cleaning & Preprocessing

1. **Biological Zero Replacement:** In `diabetes.CSV`, zero values in `Glucose`, `BloodPressure`, `SkinThickness`, `Insulin`, and `BMI` represent missing readings. These are converted to `NaN` and imputed using **Median Imputation**.
2. **Text Normalization:** In `kidney_disease.csv`, hidden tab characters (such as `\t?`, `\tno`, `\tyes`, `ckd\t`) were stripped and standardized.
3. **Categorical & Numerical Handling:** Using Scikit-Learn `ColumnTransformer`:
   - Numerical columns: `SimpleImputer(strategy='median')` followed by `StandardScaler()`.
   - Categorical columns: `SimpleImputer(strategy='most_frequent')` followed by `OneHotEncoder(handle_unknown='ignore', sparse_output=False)`.
4. **Target Harmonization:**
   - Kidney target: `'ckd' -> 1`, `'notckd' -> 0`.
   - Liver target: `1 (Liver Patient) -> 1`, `2 (Non-patient) -> 0`.

## Machine Learning Methodology

- **Train/Test Split:** 80% Training / 20% Testing with fixed `random_state=42` and `stratify=y` to preserve natural class balance.
- **Model Selection:**
  - **Random Forest Classifier** was selected for Diabetes, Heart Disease, and Kidney Disease due to superior performance in capturing non-linear interactions across biochemical lab assays while avoiding overfitting via constrained tree depths.
  - **Logistic Regression (balanced)** was selected for Liver Disease to handle the 71:29 class imbalance and provide calibrated risk probabilities.

## Installation & Setup

1. **Clone or navigate to the repository:**
   ```bash
   cd Healthcare_Patient_Risk_Prediction
   ```

2. **Create and activate a virtual environment (recommended):**
   ```bash
   python -m venv venv
   # On Windows:
   venv\Scripts\activate

   source venv/bin/activate
   ```

3. **Install dependencies:**
   ```bash

   ```

To retrain all four disease classification models and recalculate the exact test metrics:

## REST API Documentation

### 1. `GET /`
Returns the main healthcare risk prediction web application.

### 2. `GET /health`
Returns service status and loaded model keys.
- **Response `200 OK`:**
  ```json
  {
    "status": "healthy",
    "models_loaded": ["diabetes", "heart", "kidney", "liver"]
  }
  ```

### 3. `GET /model-info`
Returns metadata and actual evaluation metrics for all four disease models.

### 4. `POST /predict`
Generates a clinical risk assessment.
- **Headers:** `Content-Type: application/json`
- **Request Body Example (Diabetes):**
  ```json
  {
    "disease": "diabetes",
    "patient_name": "Jane Doe",
    "Pregnancies": 6,
    "Glucose": 148,
    "BloodPressure": 72,
    "SkinThickness": 35,
    "Insulin": 0,
    "BMI": 33.6,
    "DiabetesPedigreeFunction": 0.627,
    "Age": 50
  }
  ```
- **Response `200 OK`:**
  ```json
  {
    "status": "success",
    "patient_name": "Jane Doe",
    "disease_id": "diabetes",
    "disease_name": "Diabetes",
    "prediction": 1,
    "risk_level": "Elevated Risk Detected",
    "risk_class": "risk-high",
    "probability": 78.4,
    "confidence_text": "78.4% estimated risk",
    "algorithm": "Random Forest Classifier",
    "summary": "Based on the provided clinical parameters, the Random Forest Classifier model classifies Jane Doe as having an ELEVATED risk for Diabetes.",
  ```

## Render Deployment Guide

The repository is configured for immediate deployment to **Render** as a Web Service:

1. Push this repository to GitHub or GitLab.
2. Log in to [Render Dashboard](https://dashboard.render.com).
3. Click **New +** > **Web Service**.
4. Connect your repository.
5. Configure the service:
   - **Name:** `healthcare-patient-risk-prediction`
   - **Environment:** `Python 3`
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `gunicorn app:app`
6. Click **Deploy Web Service**.
7. Render will provision the environment, bind to `0.0.0.0:$PORT`, and provide a public URL (e.g., `https://healthcare-patient-risk-prediction.onrender.com`).

## System Limitations & Future Scope

### Limitations
1. **Sample Size:** Datasets range from 303 to 768 patient samples. While standard in academic benchmarking, clinical deployment requires validation across broader, multi-demographic cohorts.
2. **Cross-Sectional Data:** Predictions represent static point-in-time measurements rather than temporal trajectory trends.
3. **Demonstration Scope:** Intended for educational decision support, not unassisted primary diagnosis.

### Future Scope
- **Explainability Layer:** Integrate SHAP (SHapley Additive exPlanations) waterfall plots to highlight top biomarker drivers for each patient.
- **FHIR Standard Integration:** Enable automated ingestion of lab test results from Hospital Information Systems (HIS).
- **Longitudinal Trend Tracking:** Track risk progression across serial visits.
